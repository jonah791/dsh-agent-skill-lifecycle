## 2 定位与反定位

### 定位
给技能库装上**健康度**：142 个技能目前是无状态的平列表——不知道谁在用、谁好用、谁早该退场。本插件以 Beta(1,1) 后验 η 与三态状态机管理每个技能的生命周期，并观测真实使用。

- **与熔炉的分工**：`dsh-agent-skill-forge` 管**生**（从轨迹炼化技能）；本插件管**养**（技能的健康与去留）
- **松耦合**：不依赖熔炉，直接扫描技能目录纳入新技能（§5.34 依赖显式、禁读别人内部）
- **决策归主体**：只提供读数与状态机，归档/康复由爱丽丝显式发起

### 反定位
- **不删除技能**：`archived` 只是状态，SKILL.md 原文件永不自动删除
- **不改技能内容**：只读 frontmatter 的 `name`，不写 SKILL.md
- **不自动归档**（v0.1）：闲置只报告不处置（技能多为参考文档型，长期不用 ≠ 无价值）
- **不是评测器**：不判断技能内容质量，只记使用与显式反馈

## 3 术语

| 术语 | 含义 |
|---|---|
| η | Beta(1,1) 后验期望：`(passed + 1) / (attempted + 2)`，值域 [0,1]，0.5 = 完全未知 |
| trial | 一次显式试用判定（pass / fail），由爱丽丝记录 |
| use | 一次技能加载观测（`skill` 工具调用成功），自动采集 |
| 三态 | `candidate`（试用）→ `active`（可信）/ `archived`（退场，可康复） |
| 台账 | `$DSH_HOME/skill-lifecycle.json`（sidecar，不写进 SKILL.md） |

## 4 概念模型与不变量

### 数据模型
```text
SkillEntry = {
  status: 'candidate' | 'active' | 'archived'
  eta: number
  trials: { attempted: number; passed: number }
  uses: number
  source: 'scan' | 'manual'
  createdAt: string
  lastUsedAt: string | null
  missing?: boolean          // 目录里已不存在（留痕不删）
}
SkillLedger = { version: 1; updatedAt: string; skills: Record<name, SkillEntry> }
```

### 不变量
- **I1 先验诚实**：无 trial 数据时 η = 0.5（Beta(1,1) 期望），**不假装知道**哪个技能好用
- **I2 后验平滑**：η 恒为 `(passed+1)/(attempted+2)`，早期 trial 不会把 η 甩到 0 或 1（0/3 → 0.2，2/3 → 0.6）
- **I3 只增不减的留痕**：`missing` 标记取代删除；`uses` 单调不减
- **I4 状态机封闭**：状态迁移只经 `nextStatus()`，无隐式路径
- **I5 观测不反噬**：台账读写失败一律吞错返回 false，绝不影响会话（§5.22 规则 3）
- **I6 不阻塞前台**：扫描与写入为本地同步小操作，无网络、无 LLM

## 5 契约

### 工具 `skill_lifecycle`
| action | 参数 | 行为 |
|---|---|---|
| `list` | `status?` `limit?` | 列技能（默认按 η 升序 = 最该关注的在前） |
| `record` | `skill` `verdict: pass\|fail` | 记一次 trial：attempted+1、passed 视 verdict+1、重算 η、跑状态机 |
| `sync` | — | 扫描技能目录：新增纳入（candidate, η=0.5）、消失标记 `missing` |
| `archive` / `restore` | `skill` | 显式状态流转（康复回 candidate） |

### 观测（自动）
| 接缝 | 触发 | 动作 |
|---|---|---|
| `tools/result` | `exec.name === 'skill'` 且 `result.isError !== true` | 取 `exec.arguments.name` → `uses++`、`lastUsedAt = now` |

### 调用点清单
1. `apply()` → 注册 `skill_lifecycle` 工具（工具面唯一入口）
2. `apply()` → 订阅 `tools/result`（使用观测）
3. 纯层 `lifecycle.ts::etaOf / nextStatus / recordTrial / syncNames` ← 被工具与观测驱动，离线可测
4. 扫描层 `registry.ts::scanSkillNames` ← 只读技能目录的 frontmatter

## 6 边界与信任

### 能力边界
- **信号稀疏（诚实声明）**：没有自动的结果信号（不像 MemOS 有 LLM 奖励打分）⇒ η 由**显式 trial** 驱动，`uses` 只反映热度不含成败
- **`uses` 的域（2026-09-26 标注）**：从**本插件上线时刻**起算，历史使用不可回溯——「从未使用 N」的准确读法是「自我观测以来未使用过 N 个」
- 技能名取自 SKILL.md frontmatter 的 `name`；与目录名不一致时以目录名兜底（不静默丢弃）
- 覆盖**三个来源**（顺序即优先级）：`~/.agents/skills`（user）→ `<cwd>/.agents/skills`（project）→ `$DSH_HOME/skills`（本机全局）

### 信任边界
- 台账是本地 JSON，不含技能正文，仅元数据
- 所有 I/O 包 `guarded()`；异常只落日志与返回值（§5.24）

## 9 实践修订记录
- **2026-09-26** 初版：借鉴 MemOS 技能生命周期（Beta(1,1) 后验 + candidate/active/archived + 显式康复）；相对 MemOS 的两处**有意差异**——① 去掉自动 reward drift（我无自动奖励信号）② 闲置不自动归档，只报告
- **2026-09-26（同日修复）漏扫第三来源**：首轮 sync 得 142，恰好与 `~/.agents/skills` 数量吻合，因而"看起来是对的"——但技能实有**三个**来源，`$DSH_HOME/skills` 的 4 个被漏掉（**真值 146**）。发现路径：为验证使用观测而加载 `skill-maintenance`，其正文 §1 明确列出三来源，且该技能恰好不在台账 ⇒ 观测对它无效。**教训**：「与某个已知数吻合」≠「覆盖完整」——判据必须写明它比对的是**哪个集合**（§5.9 规则 6 的域标注）。已补第三根 + 三条根解析判据（测试 29 → 30），修复后 sync 得 146（新增 4）。
- **2026-10-15 P3：加载失败不再丢弃 —— η 的输入含自动结果信号**。触发是域图 G6「技能缺结果信号」（`uses` 只反映热度不含成败）。**侦察推翻了两件事**：① 初版判据（「成功轮/失败轮的 η 分化」）**前提不成立**——现有采集索引的 `turns[]` 只有 `errors` 计数、**没有工具名**，关联不了「哪轮用了技能」；② 更本质的是**因果**：技能是**指导**不是**动作**，其效果混在后续行为里，轮级错误与技能无因果（接进去是灌噪声）。⇒ 改接**唯一与该次使用直接因果相关**的信号：**加载成败**（旧实现 `if (isError) return` 把它直接丢了）。**两处刻意的设计**：① **不对称**——失败降 η，**成功加载不抬高 η**（若当 pass 计入，所有 η 会被拉向 1，区分力淹没）；② **口径分开**——`loadFailures` 独立成档不并进 `trials`（并了就分不清「谁在说话」：显式判定 vs 自动观测）。**验收**：7 条新判据（含 2 条尸体）+ 尸体对照（两处注入 ⇒ 恰好红 4 条、撤销 ⇒ 37/37）。**剩余不可得**：「技能好不好用」的**因果**信号在本架构拿不到（见 §10 未决 2）。
- **2026-10-15 P5：续更候选 —— Offline→Online 的入口**。触发是域图 G4「离线产出物用完即止」。**侦察改变了判断**：我原以为缺的是「在线更新技能内容的能力」，查证后——`skill_commit` **本就能覆盖已有 SKILL.md**（写入路径存在）⇒ 缺的是**触发器**：没有任何信号说「这个技能该回去改它」。⇒ 加 `renewalCandidates`（纯函数，**只报不改**）+ 接入点（`action=list` 的 note）。**三条规则**（各附可复算的数、互不掩盖）：① `loadFailures > 0`（**确定性失败**，权重最高——它不是「效果可能不好」）② 用了 ≥3 次却零 trial（「在线用而不更新」的最常见形态）③ 从未用过 + 创建超 30 天（该复核值不值得留，**仍不自动归档**）。**两处守卫**：`createdAt` 不可解析 ⇒ **不报第 3 条**（「算不出来」不许当成「很老」——与 P4 的 `noisy: null` 同一纪律）；`missing` ⇒ 跳过（目录已不在，续更无从谈起）。**验收**：8 条新判据（含 2 条尸体）+ 尸体对照（两处注入 ⇒ 恰好红 2 条、撤销 ⇒ 45/45）。**闭环**：离线炼化 → 在线用 → **在线观测** → 候选浮出 → 我重炼 → 回到离线。

## 10 未决问题

2. **「技能好不好用」的因果信号**（部分推进 · 2026-10-15 P3）：**加载成败**已接上（自动、单向）；但**效果**信号仍不可得——技能是指导不是动作，其效果混在后续行为里，轮级错误与它无因果（实测：采集索引 `turns[]` 只有 `errors` 计数、**无工具名**，连「哪轮用了技能」都关联不上）。候选方向：从任务板 complete/cancel 或主人反馈中半自动提取——那是**任务级**信号，需要任务↔技能的关联，本插件结构上看不见
